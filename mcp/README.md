# خادم MCP لزمام

Cloudflare Worker يفتح زمام لكلود وChatGPT بإذن المستخدم. الرابط الذي يُضاف في كلود أو ChatGPT:

```
https://mcp.zimam.work/mcp
```

## كيف يعمل الربط

1. يضيف المستخدم الرابط موصلاً مخصصاً، فيسجّل كلود أو ChatGPT نفسه تلقائياً (Dynamic Client Registration، أو Client ID Metadata Document).
2. تفتح صفحة `/authorize` بالعربية: اسم التطبيق الطالب، والجهة التي سيُرسل إليها الإذن، والصلاحيات (الاطلاع، والإضافة والتعديل).
3. يضغط «المتابعة بحساب أبل» فتفتح نافذة أبل، أو «المتابعة بحساب قوقل» فتفتح صفحة الدخول من Google في نافذة منبثقة (أو في الصفحة نفسها إن مُنعت النوافذ المنبثقة) وترجع إلى `GET /google-callback`، ويرجع رمز هوية يتحقق منه خادم زمام (`signInWithApple` أو `signInWithGoogle`). يُربط الرمز بهذه الصفحة وحدها: الـ nonce الذي يوقّعه المزوّدان هو تجزيء رمز الصفحة. خيار Google يظهر فقط إن ضُبط `GOOGLE_WEB_CLIENT_ID` في `wrangler.jsonc` (معرّف عميل الويب، ليس سراً)، ويجب أن يكون `https://mcp.zimam.work/google-callback` ضمن **Authorized redirect URIs** لهذا العميل في Google Cloud (`docs/setup.md`). صفحة العودة تُحمّل سكربتها من `GET /google-callback.js` بسياسة محتوى لا تسمح بسكربت مضمَّن، وتسلّم الرمز لصفحة الموافقة عبر `BroadcastChannel`، أو ترسل نموذج الموافقة بنفسها بعد الدخول في الصفحة نفسها.
4. يُصدر `workers-oauth-provider` رمز وصول لهذا المستخدم، وتُحفظ الرموز في KV مجزّأة.

الصفحة لا تُضمَّن في إطار، ولا يُقبل النموذج من متصفح آخر (ملف تعريف مربوط بالمتصفح).

## حدود الطلبات

تسجيل العملاء (`/oauth/register`) وصفحة الموافقة (`/authorize`) ونقطة الرموز (`/oauth/token`) مفتوحة لأي أحد، فلكل عنوان IP حدّ (`src/limits.ts`)، بربط Workers Rate Limiting في `ratelimits` في `wrangler.jsonc`:

| المسار | الحد | المفتاح |
| --- | --- | --- |
| `POST /oauth/register` | ١٠ في الدقيقة (`REGISTER_LIMITER`) | العنوان |
| `/authorize` | ٦٠ في الدقيقة (`AUTH_LIMITER`) | العنوان |
| `/oauth/token` | ٦٠ في الدقيقة (`AUTH_LIMITER`) | العنوان و`client_id` |

- العنوان من `CF-Connecting-IP`. الربط لا يقبل إلا مدة ١٠ ثوانٍ أو ٦٠ ثانية، ويَعدّ في كل موقع لكلاودفلير على حدة وبتقريب، فهو كابح للإغراق لا عدّاد دقيق. ولذلك الحد في الدقيقة لا في الساعة.
- التسجيل وطلب الرموز يأتيان من خوادم كلود وChatGPT لا من متصفح المستخدم، فيشترك فيهما مستخدمون كثيرون في عنوان واحد: لذلك حد التسجيل يتسع لعدة اتصالات جديدة معاً، ونقطة الرموز تَعدّ لكل عميل في العنوان (كل اتصال يسجّل عميله).
- الرد عند تجاوز الحد `429` مع `Retry-After: 60`: صفحة عربية في `/authorize`، و`{"error":"rate_limited","error_description":…}` في التسجيل والرموز بشكل أخطاء OAuth (لا رمز قياسياً لهذا في RFC 6749، و`slow_down` خاص بتدفق الأجهزة).
- دون الربط (`wrangler dev` أو الاختبارات) أو دون `CF-Connecting-IP`، أو إن تعطّل المحدِّد، يمر الطلب. نقطة `/mcp` لا تُحدّ هنا: طلباتها بإذن، والواجهة البرمجية تطبّق حدود الحساب.
- `namespace_id` رقم يخص كل محدِّد في حساب كلاودفلير (`4101` و`4102`)؛ لا تكرّره في Worker آخر وإلا تشاركا العدّ.

## الأدوات

| الأداة | ما تفعله | الصلاحية |
| --- | --- | --- |
| `get_agenda` | جدول يوم أو أكثر بالهجري والميلادي، مع أوقات الصلاة والمهام والمتأخرة | `tasks:read` |
| `list_tasks` | المهام حسب المشروع أو الحالة أو مدى التاريخ | `tasks:read` |
| `search_tasks` | البحث في العناوين والملاحظات والوسوم، بقواعد البحث العربي | `tasks:read` |
| `list_projects` | المشاريع ودور المستخدم وعدد المنجز | `tasks:read` |
| `list_places` | أماكن المستخدم المحفوظة («أماكني») بأسمائها، دون إحداثيات | `tasks:read` |
| `create_task` | إضافة مهمة بتاريخها، أو مرتبطة بصلاة | `tasks:write` |
| `update_task` | التعديل والنقل والتأجيل وإعادة الفتح. وبـ `status: "done"` يُنجزها، فيُضاف موعد المتكررة التالي كما في `complete_task` | `tasks:write` |
| `complete_task` | إنجاز مهمة، والمتكررة يُضاف موعدها التالي بتذكيراتها كما في التطبيق | `tasks:write` |
| `add_place_reminder` | تذكير عند الوصول إلى مكان محفوظ أو مغادرته، ومعه وقت اختياري فيصل مرة عند أيهما أسبق. الأماكن تُضاف في التطبيق فقط | `tasks:write` |

أدوات الكتابة لا تظهر أصلاً لمنحة بلا `tasks:write`. كل عملية تمر عبر الواجهة البرمجية (`api/`) بنفس صلاحيات التطبيق، فتظهر تعديلات كلود في التطبيق مع المزامنة التالية.

## التطوير

```sh
cd mcp
npx -y npm@11 install
npm test           # مسار الربط كاملاً والأدوات وحدود الطلبات، مع واجهة برمجية وهمية
npm run typecheck
```

| الملف | ما فيه |
| --- | --- |
| `src/index.ts` | `OAuthProvider`، وصفحة الموافقة، ونقطة `/mcp` بلا حالة (Streamable HTTP) |
| `src/limits.ts` | حدود الطلبات لكل عنوان على التسجيل والموافقة والرموز |
| `src/consent.ts` | صفحات HTML بالعربية بمتغيرات `tokens.css` |
| `src/tools.ts` | تعريف الأدوات وتعليمات الخادم للنموذج |
| `src/backend.ts` | شكل `ZimamService` في `api/src/service.ts`؛ يُحدَّث معه |

صفحات الموافقة تأخذ الشعار وخط ثمانية و`tokens.css` من مجلد `design/` مباشرة (`assets` في `wrangler.jsonc`)، والملف `design/.assetsignore` يستثني ما لا يحتاجه المتصفح.
